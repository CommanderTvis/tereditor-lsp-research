Does a language server make a Claude Code agent better, faster or cheaper?

Confirmatory run: 2,232 runs, 87 tasks, 29 projects, three Claude models, five arms.

What is being tested

tereditor is an IDE-like workbench for terminal coding agents. Its headless build runs without a window and serves language tools to an agent over MCP for one project: behind each tool sits the project language's language server (for example Pyright for Python, clangd for C and C++, kotlin-lsp for Kotlin). The study asks whether giving a Claude Code agent these tools changes how often it solves a task, what it costs and how long it takes.

The agent sees six MCP tools:

lsp_navigate
finds definitions, references, implementations, symbols and call hierarchies (callers and callees), and can send one read-only LSP query.
lsp_diagnostics
reports errors for the files an agent edited, by path or glob, or for the whole workspace, and can hide everything below a severity.
lsp_rename, lsp_code_actions, lsp_format
rename a symbol everywhere (or move a file and fix its imports), list and apply quick fixes and refactorings, and format a file. All three preview before they write and only change files inside the workspace.
lsp_status
shows the servers and starts them, and dumps the capabilities a server declared.

The language server and its runtime live in a separate sandbox; the agent reaches it only through a socket, so the tool arms get no compiler the baseline lacks.

An example from the run, with Haiku on a Python project: the agent asks for every reference to a class by name, and the server answers with the locations (lines and columns are zero-based; the previews number lines from one).

The arms

Same agent, same task, no compiler. Only the language-server tools change.

baseline
No language server. Plain Claude Code: read, edit, shell (grep).
optional
Language-server tools available. The agent may use them or not.
enforced
Language-server tools available, and the agent is told and nudged by hooks to use them.

Also in the charts: baseline-review (baseline plus a second "review your work" turn) and the IntelliJ versions of optional and enforced, where IntelliJ is the language server (Java and Kotlin projects only). On Kotlin this compares IntelliJ with kotlin-lsp, which the plain optional and enforced arms use.
